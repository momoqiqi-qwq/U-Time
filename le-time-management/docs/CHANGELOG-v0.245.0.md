# v0.245.0 · 隐私展示模式第 ④ 条：校名模糊

> 一句话：开着「隐私展示模式」时，屏幕上能定位到学校的那几个词也一起糊掉。
>
> 版本注记：本批改动落地时版本号从 v0.244.0 升到 v0.245.0；同期的「署名补别名」批次
> 又把树推到 v0.245.1，两者一起发布 —— 所以这份说明挂在 v0.245.0 名下，内容在 v0.245.1 里同样生效。

## 改了什么

隐私展示模式原来管三条 —— ① 人脸模糊 ② 数字 9 化 ③ 三维图全满。这次补第 ④ 条**校名模糊**：
凡命中 `中国人民警察大学` / `警察大学` / `警大` / `CPPU`（大小写不敏感）的**屏幕文本**，
就地包一层 `span[data-private-word]`，由 CSS 统一 `filter: blur(5px)`。

覆盖得到的地方（都是真文本节点，扫描器会经过）：侧栏插件名与视图名、校历抬头、
卡片标题、设置项说明、顶栏副标题、成绩页/通知页里的学校字样。
覆盖不到的地方（**明说，不假装**）：`title` / `aria-label` / `alt` / `placeholder` 等属性，
以及 canvas 里画出来的文字（三维图那条本来就整张全满）；这些都是属性值或位图，不是文本节点。

## 实现取舍（为什么这么做）

- **只包命中段，不整句糊**：「警大成绩 87.5 分」只糊「警大」，后面的「成绩 87.5 分」照常读，
  同一条里的数字照旧走 ②（`87.5` → `99.9`）。长词在前匹配，`中国人民警察大学` 不会退化成三次 `警大`。
- **用 `filter: blur()` 而不是换字符**：换字符会让文本宽度变化、整行重排，滚动位置与布局跟着跳；
  `blur` 不动几何，只糊像素。`display: inline-block` 是为了让 `filter` 对行内元素稳定生效
  （行内盒的模糊半径在某些引擎里按碎片各自算，会出现半截清晰）。
- **包裹层自己进 SKIP_SELECTOR**（`[data-private-word]`）：否则 MutationObserver 重扫会把
  已经包好的文本再包一层，几轮之后 DOM 内层套娃、还原时也拆不干净。回归断言按整棵树的
  `[data-private-word]` 总数卡（不是数某个父节点的子节点数 —— 那样会漏掉内层套娃）。
- **`scan()` 改成先收集再处理**：原来在 TreeWalker 迭代过程中改树，walker 的位置会失效，
  后半棵树的节点被静默跳过。四处规则共用这一次清扫，只改一次。
- **还原走整段替换**：命中段被拆成 `[文本, span, 文本]`，关掉开关时把这一段整体换回一个
  装着原始字符串的文本节点（而不是逐个摘 span），避免留下空文本节点与多余空白。
  父节点还带着 ② 的 `privacy-masked` 类时一并摘掉。

## 影响哪端

- 桌面端 / Android WebView / 小程序外壳：只动了 `src/` 里的前端逻辑与样式，三端共用同一份代码，行为一致。
- 文档、`public/`、Rust 侧、`tauri.conf.json`：**没动**。

## 数据迁移

无。开关状态还是原来那个 `privacyMask` 偏好（只有显式 `true` 才算开），存储键与迁移脚本都没碰。

## 搜索索引的一条教训

`SETTINGS_SEARCH_ENTRIES` 里**不要写学校名本身**（`警大` / `警察大学` / `CPPU`）。
settings 左栏搜索有个不变量：**未收录的分区按分区名兜底出一条**（`警大登录设置`、`警大获奖名单`）。
索引里再出现一个带「警大」的设置项，搜「警大」就变成两行以上，
`scripts/test-settings-option-search.mjs` 里 `assert.equal(f.rows().length, 1, ...)` 会直接红；
顺带还会把「隐私展示」挤到「警大通知 / 警大成绩」前面 —— 用户打「警大」想找的是插件，不是这个开关。
所以索引里只留「校名 学校 学校名 简称 全称 缩写 模糊 打码 遮挡」，
学校名本身留在 `src/views/settings.js` 的分区 `keywords` 里（只影响分区是否可见，不产生结果行）。
