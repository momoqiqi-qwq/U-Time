M01 · Tauri 容器

桌面 / 移动端的同一副骨架

Tauri 2 作为壳，把同一份前端代码包成 Windows NSIS / Linux deb+AppImage / Android APK。它提供窗口、WebView 调用系统能力的桥；但Le时间管理只用其中很少的接口——所有复杂逻辑都留在前端或 Rust 模块。

M02 · 前端

无框架的原生 JavaScript

你能看到的每一个视图都在 le-time-management/src/ 下：main.js 装配，views/ 下四象限/时间块/捕获/设置，pluginHost.js 插件宿主。所有视图直接拿 DOM 节点画，不引入 React/Vue/Svelte。

// src/main.js —— 入口装配，四视图 + 插件视图统一路由
import { mountQuadrant }   from "./views/quadrant.js";
import { mountTimeblock }  from "./views/timeblock.js";
import { mountCapture }    from "./views/capture.js";
import { mountSettings }   from "./views/settings.js";
import { bootPluginHost }  from "./pluginHost.js";

// 视图切换：仅替换 innerHTML + 触发重绑监听，不做虚拟 DOM diff
const views = { quadrant: mountQuadrant, timeblock: mountTimeblock, capture: mountCapture, settings: mountSettings };
bootPluginHost({ registerView, views });

为什么不引入框架

四象限视图最多 60 个任务、时间块视图最多 48 个块 / 日。在这种规模下，原生 DOM 重绘（甚至 Canvas）都比框架 diff 快几个数量级，且产物体积更小、冷启动更快。grep -r "react\|vue\|svelte" src/ 找不到任何引用。

M04 · Rust 后端

单二进制 · 跨平台一致

src-tauri/src/lib.rs 不做业务，只暴露命令句柄（原子读写、插件目录扫描、应用信息）和内置插件需要的本地能力。Rust 端跨 Windows/Linux/macOS 用 reqwest + rustls-tls，绕开 OpenSSL 1.1 在新发行版的缺位问题。

主要模块

  • lib.rs —— Tauri 命令注册 / 窗口初始化 / 插件目录扫描
  • mobile.html —— Android 端首次启动的引导页
  • native_schedule.rs —— 原生日程算法库，被 Android 原生壳调用
  • lan.rs —— 局域网同步（设备发现与数据交换）

编译配置

[profile.release]
codegen-units = 1   # 单 codegen 单元，提体积
lto           = true # 跨 crate LTO
strip         = true # 去掉符号表与 panic 段

在 Linux 上 release 包体积通常稳定在 6–8 MB（含 WebView 加载本身由系统提供）。

M05 · 数据与存储

单 JSON · 桌面/小程序同 schema

桌面端写入 appDataDir()/le-time-management.json，小程序写入 wx.getStorageSync('tb_data')。两份 JSON 结构完全一致，可互相导入。这意味着你可以在 Windows 上导出一份备份，发到手机上从微信小程序恢复，反之亦然。

原子写入流程

// src/store.js —— 写入临时文件后 rename，避免崩溃造成半截 JSON
async function atomicWrite(path, payload) {
  const tmp = path + ".tmp-" + crypto.randomUUID();
  await fs.writeFile(tmp, payload);
  await fs.rename(tmp, path);   // POSIX/Windows 都视为原子
}

备份导出格式

  • data.json —— 应用数据本体
  • plugins/ —— 插件目录（可选）
  • meta.json —— 版本号 / 设备 / 时间戳

整个备份是一个 zip，由 Rust 端 zip crate 打包，前端再走 tide.upload 接口保存。

M06 · 插件沙箱

把"功能扩展"做成"填文件夹"

src/pluginHost.js 负责发现和加载。内置插件写在 public/plugins/<id>/，由 BUILTIN_IDS 数组声明；外部插件放数据目录下 plugins/<id>/。所有插件以 new Function("tide", source) 隔离执行，宿主只暴露 tide 对象上的 API。

M07 · 微信小程序

不带构建工具的同源版

miniprogram/ 是一个能直接被微信开发者工具导入的项目，目录结构与桌面端高度对应，每个页面一个文件夹。需要打 zip 上传审核时也不需要 npm install —— JS / WXML / WXSS 三件套即可。

# 项目结构（节选）
miniprogram/
├─ app.{js,json,wxss}
├─ pages/
│  ├─ quadrant/        # 四象限视图
│  ├─ timeblock/       # 时间块视图
│  ├─ capture/         # 文本捕获 + 解析预览
│  ├─ task/            # 任务详情
│  ├─ settings/        # 数据统计 + 导入导出
│  └─ webview/         # 内嵌网页（如政策详情）
├─ core/
│  └─ timeParser.js    # 移除了正则 lookbehind 的桌面同源版
└─ images/tab/         # tabBar PNG（脚本生成）
iOS 16.4 以下的 JavaScriptCore 兼容性

桌面端 timeParser.js 用到了正则 lookbehind；小程序 JavaScriptCore 在 iOS 16.4 之前不支持，会导致模块加载崩溃。miniprogram/core/timeParser.js 重写时去掉了这些用法，行为与桌面端保持一致。

横切能力 / Cross-cutting

中文时间捕获

拖入/粘贴一段微信聊天文字，Le时间管理自动提取出"明天下午3点到4点 与导师讨论开题修改"里的时间、日期、事件和分类。整套规则 160+ 条，零依赖，桌面与小程序共用同一份解析引擎的同源改写版。

识别的语义维度

  • 绝对日期：今天 / 明天 / 后天 / 周X / 下周X / X月X日 / X-X月 / 农历节气
  • 相对时间：上午 / 下午 / 晚上 / 凌晨 / 中午 / 早上 / 夜里
  • 时刻：3 点 / 三点半 / 15:30 / 下午 3:30 / "3 到 4"
  • 时长：半小时 / 1 小时 / 一节课 / 两小时左右
  • 分类：基于关键词（开会 / 上课 / 实验 / 饭 / 锻炼…）给事件打初始象限
  • 语义合并：同一句话出现"明天下午 3 点 4 点 与 X"，合并为 15:00–16:00 事件

解析结果回写到时间轴

DRAG / PASTE全局监听 dragover & paste
EXTRACTcapture.js → timeParser
PREVIEW浮层展示解析字段，可点改

M09 · 质量层

零依赖测试 + 静态校验

Le时间管理刻意不引入 jest / vitest / mocha 这类框架；所有测试都是 Node 直跑的 .mjs 脚本，每个文件独立可执行，断言用 node:assert。失败立即非零退出，CI 直接看 exit code。

关键脚本

  • core 时间解析：node tools/test-miniprogram-core.js · 39 用例，覆盖日期 / 时刻 / 时长 / 合并
  • 小程序静态校验：node tools/check-miniprogram.js · 字段、文件存在性、四页面对齐
  • tabBar 图标再生：node tools/gen-miniprogram-tab-icons.js · 从 SVG → 渲染 PNG
  • 桌面行为快照：scripts/test-cppu.mjs / test-schedule.mjs / test-interactions.mjs / test-v0116-ai.mjs
  • Android 原生交叉编译：tools/build-native-android.ps1 · tools/build-native-schedule.ps1

写在最后 / Why

选型哲学：少即是多

Le时间管理的技术栈看起来"老派"——原生 JS + 原生小程序 + Rust 桌面壳。但每一个选择都对应一个具体克制：

  • 不要框架：四象限 + 时间块的任务量级下，原生 DOM 重绘 < 6ms，引入 React 反而要付 90KB+ 与一次 diff 开销
  • 不要数据库：单 JSON 文件可以装下用户整年的日程；引入 SQLite 后还要管 migration
  • 不要 OAuth 中间层：本地 tiny_http 监听 127.0.0.1，回流到桌面窗口即可完成扫码登录
  • 不要 CI 模板：构建是 npm run tauri build 一行命令；Tag 推送 → Actions 拉起就够
  • 不要 jest：测试是 node scripts/test-foo.mjs，断言 node:assert，失败直接非零退出

这套栈让一个学生项目可以在三天内从"想法"推进到"Windows 安装器 + 安卓 APK + 微信小程序 + 网页文档站 + 插件体系"。
