# v0.178.0 · 左上角品牌区只留名称，换成哥特字标 + 粉紫→珊瑚橙渐变

## 改了什么

**用户需求原文**：「请将应用左上角的名称和图标修改为仅保留名称，名称的字体格式参照上述样式。」
（参考样式是 Nephele Workshop 的 logo：深紫黑底、Blackletter 字体、粉紫 → 珊瑚橙横向渐变、轻微发光。）

改动只落在**桌面侧栏顶部那块品牌区**（`≥901px` 的 `.rail` 里的 `.brand`）：

| 改前 | 改后 |
|---|---|
| `<span class="mark">` 四色圆环图标 + `<b>U-Time</b>` + `<small>U-TIME</small>` | 只剩一颗 `<b>U-Time</b>` |
| 15px 无衬线粗体、`color: var(--ink)` / `#fff` | 28px 哥特黑体、粉紫→珊瑚橙横向渐变 |

- **图标与副标题一起删**：`.mark` 那枚 conic-gradient 圆环按需求移除；`<small>U-TIME</small>` 是
  同一名称的重复大写，黑体字标本身就是名称，再叠一行只是噪音 —— 顺带把品牌行的高度还给了导航列表。
- **字体随包**：`public/fonts/UnifrakturCook-Bold.woff2`（17 KB，latin 子集，SIL OFL-1.1，
  许可文本同目录 `public/fonts/OFL.txt`，署名已补进 `public/OPEN_SOURCE_NOTICES.md`）。
  应用原本**没有任何随包字体**，只靠系统字体栈 —— 不随包的话，没装 Office 的机器上会静默退化成
  Georgia 衬线，哥特字标就成了「普通衬线标题」。
  字体**只给这一颗字标用**，不进 `body` 的字体栈：全应用正文换成黑体是灾难。

### 渐变字标是怎么写的（四个坑，都写进了 `src/styles.css` 的注释）

1. 必须 `background-clip: text` + 透明字色，而且 `color` 与 `-webkit-text-fill-color` **两条都要写**。
2. **背景的绘制区域止于 border box** —— 字形一旦冒出盒子（黑体字上下都冒头），溢出那截没有背景
   可裁，会**直接看不见**。所以 `.brand b` 的 `line-height: 1.34` 与 `padding: 0 .1em .06em`
   是**必需余量**，不是随手写的间距。
3. 发光**不能用 `text-shadow`**：阴影画在元素背景**之上**，会把渐变整个盖住。只能用
   `filter: drop-shadow()`（深色那条规则里）。
4. 深浅色是**色相相同、亮度不同**的两套四档渐变，理由见下。

### 为什么浅色模式要另配一组颜色

参考图那组 `#E781CF / #F17EA9 / #F48A78 / #EDA15E` 是按深紫底挑的：

| 底色 | 四档实测对比度 |
|---|---|
| `#1C2833`（night 面板） | 6.02 / 5.92 / 6.25 / 7.04 |
| `#48405A`（Nephele 深色底） | 3.91 / 3.85 / 4.06 / 4.57 |
| 浅色侧栏（白面板） | 2.13 ~ 2.53 ❌ |

浅色下直接沿用就是「糊在纸上」。所以浅色另配一组**保持色相与饱和度、只压暗亮度**的四档
`#B62394 / #C61557 / #C32A10 / #9C5211`，按「侧栏最不利底色也够用」实算得出。

侧栏在浅色下其实有**两种**底色，字标两种都会压上去：

- **Nephele 风格界面关掉时** = `color-mix(in srgb, var(--panel) 95%, var(--paper))`，接近纯白；
- **默认开着时** = `--nephele-rail`（`src/styles/nephele-settings.css`，浅色 `#e4d7f4` /
  深色 `#342350`）那层 0.9 透明度的淡紫毛玻璃，压在同目录 `nephele-background.css` 的云层之上。
  实测合成色约 `#E0D0F0` —— **比纯白暗，对深色字更不利**，所以它才是浅色档真正的约束。
  云层是若干径向渐变叠出来的，测试里取比实测再暗一档的 `#DCC6E4` 当上界。

最终：白面板 ≥4:1、Nephele 毛玻璃 ≥3.5:1（字标是 28px 粗体 = WCAG 大号字，门槛 3:1）、
深色两种底色都 ≥4:1。深色那组就是参考图原色，外加一层同色系 `drop-shadow` 柔光。

## 影响哪端

- **只有桌面端**：`.brand` 在 `@media (max-width: 900px)` 里本来就是 `display: none`，
  手机 / APK 底部导航栏看不到品牌区，这次改动对窄屏零影响（已实测 1000px 过渡带与 150% 文字缩放
  都不溢出侧栏）。
- **小程序端无此元素**，不涉及。
- **没有数据迁移**：不碰任何存储字段、不碰主题令牌、不碰 `theme-derived.css` 生成物
  （渐变颜色直接写在 `.brand b` 规则里，没有新增 `:root` 变量，所以深色派生链完全没动）。

## 新增守卫

`scripts/test-brand-wordmark.mjs`（`npm test` 自动收）：

- 品牌区 DOM 只剩 `<b>U-Time</b>`，`.mark` / `small` 不许回来；样式表里也不许留对应死代码；
- `@font-face` 指向的随包字体**真的存在**且魔数是 `wOF2`，OFL 许可文本与第三方署名都在；
- 渐变字写法逐条钉住（`background-clip: text`、两条透明字色、`white-space: nowrap`、
  `display: inline-block`、字号 `calc(28px * var(--ui-text-scale))`、行高与内边距余量），
  并且**任何一条 `.brand b` 规则里都不许出现 `text-shadow` 或非 transparent 的字色**；
- 深色四档必须等于参考图原色；浅色四档按上表逐主题实算对比度（16 套主题 × 两种侧栏底色）。
