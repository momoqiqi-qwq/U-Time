# v0.269.0

## 新功能：邮箱卡片点一下就展开全文，「在邮箱打开」挪到卡片右上角

**影响端**：桌面 / Android（cppu-notify 插件 `mail.js`、`main.js`、`manifest.json`）· 版本 1.79.0

### 问题

以前点收件箱里任意一封，整块信头就是「在应用内邮箱窗口打开」的按钮 ——

- 只想看「这封写了什么」，却被扔出插件界面，进到一个窄浏览器窗口里，还得自己找到那封信；
- 回来以后列表滚动位置、筛选状态、刚复制的验证码都得重新找；
- 卡片本身没有「展开」这条路，信息量只有发件人 / 主题两行 + 时间。

### 改动

1. **卡片 = 展开/收起开关**：点整块信头就地展开正文，再点收起。展开时主题不再两行截断，
   卡片描边换成强调色，`aria-expanded` / `title` 跟着走（键盘 Tab + Enter 同样有效）。
2. **正文从哪来**：`bridge.body(id)` → `main.js` 的 `mailMessage(id)`，走 coreremail 的
   `mbox:getMessage`（这套部署不吃这个 func 时再试 `mbox:getMessageBody`），取 `content` 字段
   用 `cleanText()` 摊成带换行的纯文本；拿不到再退回整棵响应。两路都不认就照实说
   「邮箱接口没回这封信的正文」，并留一颗「在邮箱打开」的按钮，不把这一封做成死路。
3. **按 id 缓存 30 条**：同一封信来回展开不重复打接口（列表翻页后回看也命中缓存）；
   超过 6 万字截断并注明「完整内容点『在邮箱打开』」。
4. **「在邮箱打开」降级成卡片右上角的小按钮**：与信头是并列兄弟而非嵌套（嵌套 `<button>`
   在 HTML 里非法，点哪儿都会飘），窄屏也不换行；正文区里的报错态也复用这颗按钮。
5. **两处文案同步**：底部说明从「本页只读信头…点一封会在邮箱窗口打开」改成「点任意一封就地
   展开正文（纯文本），想看原版式、附件就点它右上角的『在邮箱打开』」。

### 边界

- 展开的是**纯文本正文**：只有文字与换行，没有样式、图片、附件 —— 这些仍然要到邮箱窗口里看。
- 展开**不改已读状态**（插件没有回写 flags 的通道），未读圆点照旧。
- 登录态、验证码自动复制、分页取全的链路一律未动；正文请求同样先过 `ensureMailSession`，
  会话失效时自动换票重试一次。

### 数据迁移

无需迁移。新状态（`state.opened`）只活在内存里，不写 storage；`mailViewPreferences` 字段没变。
