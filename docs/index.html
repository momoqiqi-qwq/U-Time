宿主 / Host lifecycle

插件如何进入U-Time

宿主发现插件目录，读取清单与入口文件，把受控的 tide 对象传给入口代码；插件在顶层调用注册 API 挂载视图、任务动作或事件监听。整个过程不需要 npm、打包器或构建步骤。

DISCOVER先加载内置插件目录（由 tools/sync-plugins.js 从各 manifest 生成），再扫描外部插件目录（仅桌面端）
MANIFEST读取 manifest.json；id 缺省时取目录名
ENABLE首次发现写入插件状态；enabled: false 则跳过执行
EXECUTE严格模式下以 new Function("tide", …) 执行入口
REGISTER顶层 tide.ui.* 等调用即刻生效，导航刷新

启动时发生了什么

  • 顺序固定：内置插件清单由 tools/sync-plugins.js 从 public/plugins/*/manifest.json 生成到 src/pluginCatalog.js，按 manifest 里的 order 升序加载，然后才是外部插件；ID 相同时内置优先，外部目录不会被加载。
  • 失败不阻断：某个插件 manifest 解析失败或执行抛错，只会记录到该插件自己的状态里（设置页可见），其余插件照常加载。
  • 执行错误可恢复：再次启用或「重新扫描」会重新执行入口代码，上次注册的视图、动作、监听会先被摘除，不会重复叠加。
信任边界

入口由 new Function 执行，不是安全隔离；代码仍可访问 document、window 等页面全局对象。permissions 是运行时权限闸门：插件调用未声明的能力时，宿主的 requirePermission 直接抛错（提示「插件 xx 没有 yy 权限」），调用失败但不崩宿主。声明要真实——多写是撒谎，少写是自断 API。只安装已审查、可信来源的插件。

最短路径 / Two-file start

十分钟做出第一页

文件夹名建议与插件 ID 一致。插件不需要 npm，也不需要打包；把两个文件放进数据目录下的 plugins/hello-tide/，然后在设置页点「重新扫描」。

plugins/
└─ hello-tide/
   ├─ manifest.json
   └─ main.js

manifest.json

{
  "id": "hello-tide",
  "name": "潮汐问候",
  "version": "0.1.0",
  "author": "your-name",
  "icon": "潮",
  "description": "显示今天日期，并记录视图打开次数。",
  "permissions": ["ui", "storage", "notify"],
  "entry": "main.js"
}

main.js

tide.ui.registerView({
  id: "hello-tide",
  title: "潮汐问候",
  icon: "潮",
  async render(el) {
    const visits = await tide.storage.get("visits", 0);
    await tide.storage.set("visits", visits + 1);

    el.replaceChildren();
    const card = document.createElement("section");
    card.textContent = `今天是 ${tide.util.today()}，这是第 ${visits + 1} 次打开。`;
    el.append(card);
  }
});

tide.notify("插件已加载");

两条开发路径

EXTERNAL 外部插件

放数据目录，随时热改

桌面端在「设置 → 数据」查看数据目录，把插件放进其中的 plugins/。改完 main.js 点「重新扫描」即生效，不需要重新构建应用。

BUILTIN 内置插件

放进 public/plugins，随包分发

把目录放入 le-time-management/public/plugins/（manifest 写好 order 与 platforms），然后跑 node tools/sync-plugins.js 重新生成插件目录——它会校验清单并同步桌面与小程序两端。Android 端只能用这种方式。

建议用 IIFE 包住入口

内置插件的通行写法是 (function () { … })(); 把状态与函数封在闭包里，只把注册调用暴露在顶层。这样重新执行入口不会和上一轮的闭包互相串状态。写好后可到插件工坊上传校验、一键打包成合规 zip。

契约 / Manifest contract

清单字段

manifest.json 是标准 JSON——不允许注释、不允许尾逗号，解析失败插件直接不加载。

字段用途与约束
id稳定、唯一的插件标识；推荐小写字母、数字与连字符。外部插件目录名应与它一致；目录名不一致时以清单里的 id 为准，但读文件仍按目录 ID，所以保持一致最省心。
name面向用户的名称；通知会自动加前缀显示为「插件名：消息」。
version推荐语义化版本，例如 1.2.0。设置页据此判断是否需要重扫。
author作者或组织名称。
icon图标的「门控键」：内置插件带此字段时，appIcon() 才会去读随包 PNG public/icons/plugins/<id>.png（生成管线见 图标）；建议写 1–2 个汉字作为加载失败时的字形兜底。
description说明用途、远端数据源、登录要求与敏感配置。用户决定是否信任这个插件的依据。
order内置插件专用：侧栏与加载顺序（升序），由 tools/sync-plugins.js 校验必填。外部插件不需要。
platforms内置插件专用：声明 windows / android / miniprogram 三端的可用级别（full / native / conditional / unavailable），同样由 sync-plugins.js 校验。
permissions声明使用的能力。运行时权限闸门：插件调用未在此列出的能力，宿主 requirePermission 直接抛错（例如网络桥调了但没声明 http，运行时必炸）。只写实际用到的。
entry入口脚本相对路径；省略时默认 main.js。

不要手工替换 PNG

插件与导航 PNG 都是生成物——手改会被下次生成覆盖，且与台账里的 sha256 对不上。要换素材，改生成器里的 slug（或 TEXT_ICONS 的文字）后重新生成。

署名是硬性要求

Icons8 素材按 Icons8 License 免费使用需在产品内署名（设置 → 关于页与 public/OPEN_SOURCE_NOTICES.md）；印章式文字图标为本项目代码绘制，非第三方素材。素材不得作为独立图标库转售或再分发。

接口 / tide API

宿主注入的能力

tide 是插件入口拿到的唯一约定对象。列表读取一律返回深拷贝——改拷贝不影响真实数据；写入必须走 create / update / remove，才能触发持久化与界面刷新。

身份与存储

API说明
tide.id当前插件 ID，与 manifest 一致。
tide.manifest解析后的当前插件清单对象。
storage.get(key, fallback?)异步读取插件私有存储；键不存在时返回 fallback（缺省 null）。每个插件的存储完全隔离。
storage.set(key, value)写入插件私有存储并立即触发保存。注意函数本身不返回底层写盘的 Promise，await 只等赋值完成，不等磁盘落盘；但连续多次 set 各自都会触发保存，不会丢。

界面与通知

API说明
ui.registerView(def)注册侧栏视图。def = { id, title, icon, render(el) }。render 会被宿主多次调用（每次进入视图），必须幂等：先清空 el 再重建 DOM。
ui.registerTaskAction(def)注册任务详情动作。def = { id, label, icon, run(task) }；传入的 task 只用于读取上下文，修改要走 tasks.update。
notify(message, opts?)显示 toast，自动加「插件名：」前缀；opts.ms 控制毫秒数。

安全区（APK 必读）

Android 是全面屏，状态栏、导航栏与横屏时的摄像头挖孔会盖在网页上面。WebView 里的 env(safe-area-inset-*) 恒为 0，所以原生侧按真实 WindowInsets 把四个方向注入成 CSS 变量，宿主统一垫在插件页外面 —— 画在 render(el) 给的容器里的内容一行代码都不用写。

变量含义不管它就会
--sat顶部状态栏标题与返回按钮压进状态栏
--sab底部导航栏最后一行按钮点不到
--sal / --sar左 / 右（横屏挖孔、三键栏在侧）横屏时内容被挖孔切掉
  • 禁止裸用 env()：必须写 var(--sat, env(safe-area-inset-top, 0px)) 这种双路形式 —— APK 取原生注入的变量，桌面与 iOS 靠 env() 兜底。scripts/test-plugin-safe-area.mjs 会拦这一条。
  • 禁止再垫一遍：宿主已经垫过了，插件对自己的容器再加一次会双重计算（实测：桌面端插件页底部因此凭空多出 86px 纯空白）。也不要去猜一个固定像素值。
  • 唯一例外是 position:fixed：浮层的包含块是宿主内容区元素的 padding box，padding 划不出它的新边界，所以自建遮罩 / 弹层 / 菜单必须自己让开四条边。让开的边 = 你钉住的边：声明了 bottom: 就要让开 --sab，钉了 inset: 就是四条全让 —— 只让底、不让左右是最典型的错法（竖屏看不出问题，横屏挖孔压在内容上）。
  • 别信 100vh 与 innerWidth：它们量的是视口而不是可视区，用它算弹层高度或夹取边界会把内容算到导航栏 / 挖孔底下。弹层高度用 max-height:min(82vh,100%)，夹取要先减掉 --sal/--sar/--sat/--sab。
/* 配方 A：CSS 浮层。遮罩铺满整屏是对的，让内边距去吃安全区 */
.my-mask{position:fixed;inset:0;z-index:1900;display:flex;align-items:center;justify-content:center;
  padding:calc(16px + var(--sat,env(safe-area-inset-top,0px)))
          calc(16px + var(--sar,env(safe-area-inset-right,0px)))
          calc(16px + var(--sab,env(safe-area-inset-bottom,0px)))
          calc(16px + var(--sal,env(safe-area-inset-left,0px)))}

/* 配方 B：JS 按视口坐标定位的浮层（右键菜单、跟随手指的气泡）。
   坐标是从屏幕角上量的，所以夹取边界要自己减掉安全区。 */
const px = (v) => parseFloat(getComputedStyle(document.documentElement).getPropertyValue(v)) || 0;
// 变量取不到时 parseFloat 出 NaN → 0，桌面端行为不变
const [sat, sab, sal, sar] = [px("--sat"), px("--sab"), px("--sal"), px("--sar")];
const x = Math.max(8 + sal, Math.min(rawX, window.innerWidth - sar - MENU_W));
const y = Math.max(8 + sat, Math.min(rawY, window.innerHeight - sab - MENU_H));

真机自检：APK 装好后把手机转成横屏（挖孔跑到左侧）打开插件页，内容左边缘应留出挖孔宽度；再开一个弹层，确认它既不压状态栏也不被导航栏吃掉。

网络桥

Tauri 端请求由 Rust 发出，绕开 WebView 的 CORS 限制，Cookie 也可持久保持；浏览器调试模式自动降级为普通 fetch（受 CORS 约束）。

API说明
http.get(url)一次性 GET。返回 { status, body, finalUrl, contentType }，重定向后的最终地址在 finalUrl。
http.session()创建带 Cookie Jar 的会话，返回会话 ID（异步）。登录态跨请求保持。
http.fetch(sid, method, url, opts)会话请求。method 支持 GET / POST / PUT / DELETE；opts = { headers, body, binary }。binary: true 时 body 为 Base64（验证码图片场景），响应里额外带 cookies 数组。
网络桥的三条硬约束

① 只允许 http/https 地址，其他协议直接报错；② http.fetch 的会话可能过期（重扫后旧 ID 失效），报「会话不存在」时重新 session() 即可；③ 会话表在内存里，应用重启后登录态要重建。

数据 / Data shapes

任务与时间块的完整字段

任务表达「决策」——做什么、多急；时间块表达「日程」——哪天、几点、多久。通过 taskId 关联：删除任务会带走它的时间块，改任务标题会同步时间块标题。

notestring，默认空备注。
quad1–4，默认 1四象限：1 重要紧急、2 重要不紧急、3 紧急不重要、4 其他。

duestring，默认 null截止日期 YYYY-MM-DD。

startstring，默认 "09:00"HH:mm 24 小时制。
durMinnumber，默认 30持续分钟。

解析器 / parseWhen

把一句话变成日程

tide.util.parseWhen(text) 是宿主内置的中文时间解析器，专为聊天消息和通知标题设计。返回 { date, startMin, endMin, title }——date 为 YYYY-MM-DD 或 null，startMin / endMin 为当日分钟数或 null，title 是清洗后的纯文本标题。

识别的日期写法

写法示例规则
相对日今天 / 明天 / 后天 / 大后天直接换算。
完整日期2026年9月10日、2026-9-10按字面取值。
月日9月10号、9 月 10 日今年没有则顺延到明年。
星期周三 / 下周3 / 下下周星期五「下周」永远指下一个完整周；今天也算进本周。
下月几号下个月5号按字面取下月。
月底这个月底 / 下月底取当月最后一天。
几号15号本月已过则顺延到下月。

识别的时间写法

写法示例规则
钟点下午3点、晚上8点半、9点一刻、10点40分时段词：凌晨/早上/上午/中午/下午/傍晚/晚上。下午/晚上自动 +12。
24 小时14:30、9:05冒号形式。
区间下午3点到4点半、14:00–15:30分隔词：到/至/—/--/~/～/-。结束时间继承开始时间的时段词（「下午3点到4点」= 15:00–16:00）。
语义归一今晚8点、明早九点先拆成「今天 晚上8点」再解析，避免时间词被日期吞掉。

标题清洗

  • 所有被解析掉的日期、时间片段都会从标题里剔除，不会残留「11:40」这类碎片。
  • 口语引导词（记得、帮忙、提醒我、安排一下、定在……）会被移除。
  • 标题截断到 24 字；清洗后为空时退回原文前 24 字，再兜底为「捕获的事件」。
// 「记得明天下午3点到4点半开组会」→
// { date: "2026-09-11", startMin: 900, endMin: 990, title: "开组会" }
const { date, startMin, endMin, title } = tide.util.parseWhen(raw);

if (date) {
  tide.blocks.create({
    date,
    start: tide.util.hhmmOf(startMin),
    durMin: endMin ? endMin - startMin : 30,
    title,
    cat: tide.util.guessCategory(raw)
  });
}

配套的两个猜测函数：guessCategory 按关键词分类（健身跑步→sport、吃饭快递→life、考试上课→study、休息午睡→rest、其余→work）；guessQuad(date) 两天内到期归象限 I、否则象限 II，date 为空返回 2。

实战 / Recipes from builtin plugins

四个取自真实插件的范例

下面的模式都来自当前随包分发的内置插件，按「要做什么」对号入座。完整源码在仓库 le-time-management/public/plugins/ 里。

1 · 计时器视图 —— 学 pomodoro

适合番茄钟、专注计时这类交互视图。三个关键动作：IIFE 封闭状态、render 先清空再重建、interval 存进闭包变量以便随时停。

(function () {
  let timer = null, left = 25 * 60;

  function stop() { clearInterval(timer); timer = null; }

  function render(el) {
    el.replaceChildren();                     // 幂等：每次进入视图都重建
    const btn = document.createElement("button");
    btn.textContent = "开始";
    btn.addEventListener("click", () => {
      if (timer) { stop(); btn.textContent = "继续"; }
      else {
        timer = setInterval(() => {
          left -= 1;
          if (left <= 0) { stop(); tide.notify("时间到"); }
        }, 1000);
        btn.textContent = "暂停";
      }
    });
    el.append(btn);
  }

  tide.ui.registerView({ id: "my-timer", title: "我的计时", icon: "计", render });
  tide.events.on("my-timer:reset", () => { stop(); left = 25 * 60; });
})();

2 · 后台轮询推送 —— 学 wechat-push

适合「定时检查数据、条件满足就推送」的场景（Server酱、webhook 等）。要点：插件加载即启动定时器，视图只是配置入口；用带日期的去重键防止重复推送；日志写进私有 storage。

(function () {
  const state = { enabled: false, timer: null, pushed: [] };

  async function tick() {
    if (!state.enabled) return;
    const d = tide.util.today();
    state.pushed = state.pushed.filter((k) => k.startsWith(d));  // 只保留今天
    const blocks = await tide.blocks.list(d);
    const nowMin = new Date().getHours() * 60 + new Date().getMinutes();
    for (const b of blocks) {
      const [h, m] = b.start.split(":").map(Number);
      const delta = h * 60 + m - nowMin;
      const key = d + "|" + b.id;
      if (delta >= 0 && delta <= 5 && !state.pushed.includes(key)) {
        state.pushed.push(key);
        await tide.http.get("https://你的推送端点?title=" + encodeURIComponent(b.title));
      }
    }
    await tide.storage.set("pushed", state.pushed);
  }

  function startTimer() {
    if (state.timer) clearInterval(state.timer);
    state.timer = setInterval(tick, 60 * 1000);
  }

  tide.ui.registerView({ id: "my-push", title: "定时推送", icon: "推", render });
  startTimer();  // 加载即跑，不依赖视图是否打开
})();

const days = [];
for (let i = -6; i <= 0; i++) days.push(tide.util.addDays(tide.util.today(), i));

Promise.all(days.map((d) => tide.blocks.list(d))).then((weeks) => {
  const perDay = weeks.map((bs) => bs.reduce((a, b) => a + b.durMin, 0));
  const byCat = {};
  weeks.flat().forEach((b) => { byCat[b.cat] = (byCat[b.cat] || 0) + b.durMin; });
  // 用 perDay / byCat 画图或渲染表格…

需要账号登录的教务、门户系统：先建会话登录，再复用同一会话拉数据；验证码用 binary: true 拿 Base64；协议需要 DES 加密时走 Rust 端。

const sid = await tide.http.session();

const login = await tide.http.fetch(sid, "POST", "https://example.com/login", {
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({ username, password,
    password: await tide.util.desEncryptHex(password, key) }).toString()

if (login.status !== 200) { tide.notify(`登录失败：HTTP ${login.status}`); return; }

// 验证码：binary 拿 Base64，直接塞进 img.src

img.src = "data:image/png;base64," + cap.body;

凭据安全底线

密码、令牌只存插件私有 storage 时要明说风险；不要写进日志或 console.log；远端文本一律 textContent 或转义后渲染，别直接 innerHTML。

生命周期 / Enable · disable · rescan

停用、重扫与副作用清理

用户可以随时停用插件或点「重新扫描」。宿主负责摘掉它注册的东西，但管不到你自己创建的全局副作用——这是插件出重复视图、重复通知的头号原因。

操作宿主做什么你需要自己做什么
停用移除该插件注册的视图、任务动作、事件订阅、关怀频道；下次启用重新执行入口。停用不会清理你的 setInterval、document 级监听和注入的 <style>——轮询类插件要在通知或 UI 上提示用户，或设计成停用后无害。
重新启用重新执行入口代码；先摘掉旧注册再执行，不会叠加。闭包里的旧定时器还活着（旧闭包没被销毁），启动定时器前必须先 clearInterval。
重新扫描清空全部注册与注册表，从头加载所有插件。同上；外部插件文件改动也靠这一步生效。
删除（外部插件）停用 → 删除目录 → 清掉插件状态与存储。内置插件不可删除，只能停用。无。

幂等启动模板

(function () {
  let timer = null;   // 闭包变量；重新执行入口时这是一个全新的闭包

  function startTimer() {
    // 关键：先清旧再起新。没有这一行，重扫一次就多一条轮询
    if (timer) clearInterval(timer);
    timer = setInterval(tick, 60 * 1000);
  }

  function ensureStyle() {
    // 注入全局样式前先查重，style 元素按 id 挂到 head
    if (document.getElementById("my-plugin-style")) return;
    const st = document.createElement("style");
    st.id = "my-plugin-style";
    document.head.append(st);
  }

  startTimer();
})();

事件 / In-process bus

事件总线的能与不能

tide.events 是当前进程内的发布订阅：适合插件间松耦合协作，不适合当可靠队列。

  • 命名约定：事件名用 插件ID:事件名，例如 pomodoro:finished，避免跨插件撞名。
  • 监听器异常被吞：emit 时逐个 try/catch，某个监听器抛错不影响其他监听器，错误只进 console。
  • 没有退订：events.on 不返回退订函数；停用插件时宿主按插件 ID 批量摘除。
  • 不持久、不跨进程：应用重启即清空；微信推送这类外部通道收不到。
  • 不保证顺序：同一事件的监听器按注册顺序同步执行，但跨事件没有顺序保证。
宿主当前不广播数据变更

写这份手册时，宿主还没有在任务/时间块变化时向插件广播事件（总线里没有 tasks:changed 这类宿主事件）。需要感知数据变化的插件（如轮询推送、任务看板）应自行定时重读 tasks.list() / blocks.list()，或在 render 时重读。这是已知边界，后续版本可能补上。

矩阵 / Platform boundaries

先决定插件运行在哪

WINDOWS / LINUX DESKTOP

完整路径

外部插件扫描与文件读取、Rust 网络桥（绕 CORS）、Cookie 会话、DES 工具、系统浏览器、关怀频道全部可用。插件开发的默认目标平台。

ANDROID

随应用内置

不扫描外部目录。插件必须放进 public/plugins/ 并经 node tools/sync-plugins.js 写进插件目录（platforms 声明 android 级别），随 APK 构建。网络桥与 DES 在移动端同样走 Rust，行为一致。

BROWSER DEV

有限降级

数据落 localStorage；listPlugins 返回空（外部插件不可用）；HTTP 走浏览器 fetch，受 CORS 约束；desEncryptHex 直接抛错；会话 ID 是本地随机串，无真实 Cookie Jar。

WECHAT MINIPROGRAM

不可直接复用

小程序版共享数据格式与时间解析思路，但没有插件宿主。要把能力带过去，只能改写成小程序页面，或让它连接桌面端的局域网服务。

面向 Android 开发的额外纪律

进入插件目录的内置插件，Android 用户无法删除只能停用。插件要经得起「长期驻留」：轮询频率克制、失败静默降级、不要在 render 里做重活。

排错 / Debugging

出问题时先看这三处

插件加载失败不会弹窗打断使用——它安静地记录在设置页和 DevTools console 里。

  • 设置 → 插件：加载失败的插件会显示错误信息（manifest 解析失败、入口执行异常都在这）。
  • DevTools console：宿主以 插件 xxx 加载失败: 为前缀输出完整堆栈；你自己的 console.log 也在这里。桌面端按 F12 打开。
  • 重新扫描：改完文件后手动触发，外部插件不会自动热更新。

常见报错速查

报错原因与处理
manifest 拉取失败 (404)内置插件：目录没进 public/plugins/，或改完没跑 node tools/sync-plugins.js 重新生成目录。
插件「xx」没有「yy」权限运行时权限闸门生效：调用了 manifest permissions 未声明的能力。补声明，或删掉该调用。
JSON.parse 异常manifest 里有注释或尾逗号——必须是严格 JSON。
插件 xxx 加载失败: SyntaxErrormain.js 语法错误，看 console 堆栈定位行号。

仅支持 http/https 地址网络桥协议白名单，检查 URL 拼接是否漏了协议头。
DES 加密仅支持在 Tauri 环境使用浏览器调试模式没有 Rust 桥；真机上正常。
命令 xxx 仅在 Tauri 环境可用同上——调试浏览器里走不到 Rust 命令。
视图出现两份 / 通知来两条定时器或注册没做幂等清理，见生命周期一节。
调试建议：先跑浏览器，再上真机

浏览器模式数据落 localStorage、改代码刷新即见，适合磨 UI 和纯逻辑；涉及网络桥、会话、DES、外部插件目录时再切桌面端验证，Android 功能最后随 APK 实测。

交付 / Test & release

发布前逐项过一遍

  1. 清单可解析
    JSON 无注释、无尾逗号；ID 与目录名一致；entry 指向的文件存在；version 已更新。
  2. 声明真实能力
    只列实际使用的 permissions；description 写清远端服务、登录要求与敏感配置。
  3. 验证完整生命周期
    首次加载 → 停用 → 重新启用 → 重新扫描 → 应用重启，全程不出现重复视图、重复定时器、重复通知。
  4. 检查数据写入
    创建、更新、删除任务/时间块后重启应用，确认持久化正确；删任务时关联时间块一并消失符合预期。
  5. 覆盖失败分支
    断网、非 2xx、返回结构改变、登录过期、空列表、存储损坏——每种情况都有可行动的用户提示，而不是静默失败。
  6. 检查页面安全
    远端文本用 textContent 或转义后渲染；外链限可信 http/https；凭据不进日志。
  7. 界面没超出安全区
    页内容交给宿主垫，插件不重复加；自建 position:fixed 浮层必须让开 --sat/--sab/--sal/--sar，且不许裸用 env(safe-area-inset-*)。横屏真机各开一页、各开一个弹层确认。
  8. 做目标平台实测
    外部插件在真实数据目录验证；内置插件必须随 APK 构建后在 Android 真机过一遍。
