# v0.172.0 · 搜索缩写按词匹配，点结果必到

## 改了什么

- 拼音缩写搜索不再「一串到底」。以前把标题和关键词拼成一条长串再找子串，于是搜「zt」会命中「顶部任务统计居中」（首字母串 dbrwtjjz 里恰好有 zt）、「界面缩放」（关键词「整体缩放」→ ztsf）这类不相干条目，真正要找的「字体模式」「文字大小」反被挤到第八位。
- 现在缩写只认**词的开头**：`字体模式` → zt（标题前缀）、`字体着色` → ztzs、`文字大小`（关键词写着「字体」）→ zt。搜「zt」的命中从 10 条收敛到 6 条，且都是真的跟字体 / 主题相关的。
- 补上界面上真实存在、却漏收进索引的「字体模式」一行（衬线 / 等宽 / 系统字体），搜「字体」时能直接落到它。
- 左栏搜索的分类筛选也吃拼音缩写了。以前搜「zt」时左侧 14 个分类一个都不剩（显示「0 / 14」），右侧却列着命中的设置项 —— 两边自相矛盾；现在分类与设置项任一有命中就不算空，计数也改成「匹配 N 项设置」。
- **点搜索结果必定跳到那个控件**。以前搜「zt」点「主题」，分区根本不切、控件也不滚 —— 因为左栏那次文字筛选把目标分区挡在了可见集合外，切换被直接拦下。现在「用户明确点了某一条」不受筛选约束。
- 落点解析不再依赖一份手写的容器白名单。旧清单漏了「关于」页的运行平台 / 数据策略 / 设备联动、快捷键卡的命令面板 / 快速捕获、局域网卡的状态行等，这些条目点下去都没反应；现在按元素自身文本找最深的一层，新增版式不用再回来补清单。
- 命中的控件在当前状态下不显示时（「配好了，以后怎么同步」要配好网盘才展开），退回分区本身并高亮，而不是把滚动和高亮落在一个 0×0 的元素上。
- 命令面板（Ctrl+K）与设置页左栏共用同一套打分与分区名映射表，两处口径不会再各漂一份。

## 影响范围与数据迁移

- Windows / Web / Android 共用同一套设置页与命令面板，三端同时生效。索引里「测试」分区（手机预览尺寸等）现在也能搜到具体控件。
- 无数据迁移；不改任何存储字段，搜索状态只在设置弹窗打开期间保留。
