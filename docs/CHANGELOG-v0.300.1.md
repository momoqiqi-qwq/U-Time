# v0.300.1 · 考勤风险再修四处 + 字标改动一并出包

> 发布日 2026-11-11 · 影响端：Windows / Android（两端同为 v0.300.1）· 无数据迁移

## 改的是什么

「考勤风险」第二轮缺陷检测抓到四处。都在插件 `cppu-notify`（1.92.1 → 1.92.2），宿主壳只跟着升版本号；v0.300.0 的左上角字标改动（U-Time + 系统无衬线）本次一并打进安装包，它会话内可查 `docs/CHANGELOG-v0.300.0.md`。

| # | 现象 | 根因 | 现在 |
|---|---|---|---|
| E | 只排过 1 次课的课程，本学期唯一那条请假单被说成「别的学期」 | 学期边界拿不到时退到「课次上课日 min/max」，单次课跨度 0 天 → 范围只有那天 | 跨度不足 28 天就不敢拿它当学期，宁可不过滤；页脚写明「没拿到学期起止日，请假记录未按学期筛」 |
| F | 4 条没有审批状态的记录，直接判「已超红线」 | 缺 `SQZT` 时落到「其余按旷课计」分支 | 缺状态单列 `unknown`，不计入任何一档，页脚报「N 条记录没带审批状态，未计入」 |
| G | 一节课撤销后重提，一次缺勤被记成「1 次已批 + 1 次旷课」 | 两张单子都算 | 按「课程 + 上课日」判重，取最有利的一条（已批 > 审批中 > 未通过），页脚报合并条数 |
| H | 放假后第一次打开，课表与考勤按上学期算且无提示 | `term` 跟着缓存落盘，`loadJwTerm` 见它非空就不问教务 | 学期缓存只在「教务给的学期结束日 + 7 天」内可信（老缓存按写入时间兜 30 天），过期即重新拉取 |

## 修法要点

- `jwRiskTerm`：两端齐 → 直接用；只有一端 → 向另一侧铺 200 天；两端都缺才看课次日期，且要求跨度 ≥ 28 天。
- 判重用 `seen` Map，键是 `课程名 + \u0000 + 上课日`；上课日缺失的记录不参与判重，各自计数。
- `jwTermFresh(t)`：`termEnd + 7 天` 未过且（无写入时间或 30 天内）才算新鲜。
- `rows.diag` 扩成 `{ stale, unmatched, unknown, merged, term }`，页脚四条提示各自独立。

## 守卫测试

`scripts/test-cppu.mjs` 新增源码断言 4 条（`jwTermFresh` 存在、两处调用点、页脚文案）与真跑断言：单次课不误排、缺 `SQZT` 不算旷课、同节撤销重提只算一次、陈旧学期缓存被拒 / 学期内缓存被复用、无学期边界时的提示文案。

## 没做什么

- 额度折算（总学时 ÷ 3 再 ÷ 2 截断）、两条红线、等级四档、三级排序核对过与原版 `AttendanceRisk` 一致，未动。
- 只排 1–2 次课导致额度为 0 时，缺 1 次仍判「已超红线」（原版同口径），只在卡片里写清为什么。
- 自习室「只看空」按静态审阅与边界用例复核（空名 / 空节次 / 未知状态码 / 单行数据）未发现硬缺陷，未改。
