## 一、删的判据（不是「看着啰嗦」）

样本插件 `wechat-push` 是 18 个内置插件里最小的（单视图 / `main.js` 475 行），
所以它的毛病就是其它 17 个的毛病。删之前先把每块文字量出来，然后对每一行问同一个问题：

**「这行删掉，功能还看得懂吗？」**

- 复述旁边按钮/字段的（「点『一键获取 Token』打开一对一消息页，微信扫码登录后复制 Token 粘贴回来」
  —— 旁边就是那个按钮，点下去就是那个页面）→ **删**。
- 介绍产品优点/使用建议的（「推荐使用 PushPlus」「兼容旧版 Server酱配置」）→ **删**。
- 只有在特定错误下才有意义的（1 小时 3 条 / 每分钟 5 次的频次规则，代码里 `pushLog` 附近的 hint 分支
  本来就只在 `999` 报错时吐出来）→ **删**，错误发生时自然会说。
- 操作步骤、状态语义、会误导用户的边界说明（「扫码登录后复制 Token」「✓ 只表示已提交，实际送达以微信为准」
  「仅本地模拟，不发送消息」）→ **留**。这三句是全页最不能删的：删掉它们，用户会以为本地预览真的发了消息。

删除的 11 块（逐块量出的省字）：kicker 整行 −15、推荐说明整段 −110、文档行 −19、渠道按钮后缀 −5、
Token 旁提示 −21、Topic 行 −9、攒批说明 −71、日志说明 −80、预览说明 −53、分组标题 −9、按钮文案 −9。

### 3.1 一处「文案与实现不一致」的修正

`显示/隐藏凭据` 这个名字原来是**两个动词并列**——点下去只切 `input.type`，文案恒定，
所以既不会说谎、也不好看（像两个按钮）。改成单动词「显示凭据」之后，**必须真的跟着状态走**，
否则按钮在说谎：

```js
wrap.querySelector("[data-show]").addEventListener("click", (e) => {
  const next = ui.token.type === "password" ? "text" : "password";
  ui.token.type = next; ui.key.type = next;
  e.currentTarget.textContent = next === "text" ? "隐藏凭据" : "显示凭据";
  e.currentTarget.setAttribute("aria-pressed", next === "text" ? "true" : "false");
});
```

按钮初始文案带 `aria-pressed="false"`；这是本版唯一的**行为**改动，其余全是文本。

## 四、测试（`scripts/test-wechat-push.mjs` 第 8 节 25 条）

删描述这件事最容易「下次改别的东西时把说明又加回来」，所以每条都配反向守卫
（`assert.doesNotMatch` 守住旧的啰嗦句不许复活，`assert.match` 守住必须留的短句不许误删）：

```js
assert.doesNotMatch(source, /微 信 信 息 推 送/, '字距拉开的 kicker 整行必须删');
assert.doesNotMatch(source, /推荐使用 PushPlus/, '卡片顶那段 110 字的推荐说明必须删');
assert.doesNotMatch(source, /一键获取 Token/, '「一键」是自夸，按钮只留动词短语');
assert.match(source, /扫码登录后复制 Token/, 'Token 旁短提示必须还在 —— 那是真的操作步骤');
assert.doesNotMatch(source, /官方接口为异步，code=200 只代表已接收/, '频次规则只在 999 报错时吐出来');
assert.match(source, /✓ 只表示已提交，实际送达以微信为准。/, '「✓ = 已提交、不等于已送达」这句不能删');

assert.match(source, /e\.currentTarget\.textContent = next === "text" \? "隐藏凭据" : "显示凭据"/,
  '按下去要变成「隐藏凭据」：原来只切 input type、文案恒定，单动词写法下就会说谎');
```

## 五、验证方式（活页，不用静态快照）

`plugin-preview.mjs` 产出的是**静态 DOM 快照**（没有 JS、没有 tide stub、点不了按钮），
所以本次另做活页装置：拿 harness 的 `<head>`（应用 CSS + 插件 CSS 已内联）+ 自写 body
（`tide` stub + **真** `main.js`），交给真实 Chrome 跑一遍并自动点开「微信预览」/「推送内容」面板，
再截图 + 逐项读图核对。必须走 http 服务（插件里 `src="/icons/plugins/wechat-push.png"` 是根绝对路径，
`file://` 下取不到图）。

读图之外还做了一次 **DOM 事实核对**（把快照里插件区域的文本节点全抽出来）：
面板分组标题「插件消息」「攒 2 分钟后合并发送，省频次额度。」「显示凭据」三处在图上被读花过，
用 DOM 文本确认真身无误 —— 视觉模型的模糊不是文案错。
