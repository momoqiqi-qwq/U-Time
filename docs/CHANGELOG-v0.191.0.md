## 用户要求原文

> 「添加编辑模式，自由拖动不同星星到不同床铺，自由重命名，自由连线。」

## 一、先说清楚「床位」原来是怎么定下来的

星图一直是**纯显示**：`i` 号床上睡的就是成员名单里第 `i` 个人（`roomBeds(size)` 决定第 `i` 张床是下铺还是上铺、
贴哪面墙），成员顺序 = 床位顺序，谁也没法改。所以「自由拖动星星到不同床铺」这件事，本质上是**给床位槽一份自己的数据**，
而不是把星星挪个位置那么简单 —— 星点是每帧按投影算出来的，拖完不落盘、或者落盘了但下次进来又被名单顺序覆盖，都白干。

于是新增三个组内字段（都放在原来的 group 对象里，跟着整组备份/导入导出一起走）：

| 字段 | 形状 | 含义 |
|---|---|---|
| `seats` | 长度 = 房间人数档的字符串数组 | 第 `i` 格是睡在 `i` 号床上的**成员 id**，空串 = 空床 |
| `bedNames` | 同上 | 空床的**别名**（「行李架」「杂物」），只在空床上显示 |
| `links` | `[[a, b], …]` | 自定连线（无向，保方向只为了虚线流动方向），上限 24 条 |

## 二、床位槽的取人规则：先落座，空槽再按名单顺序补

`seatsOf(g, size)` 是**唯一取人入口**（渲染、拖动、下拉、复制整套轮换全走它）：

```js
// 1) g.seats 里点过名的人按槽坐（跳过空串、跳过重复 id、跳过已经不在名单里的 id）
// 2) 剩下的空槽，按**成员名单顺序**从头扫，逐个补位（跳过已经坐下的）
```

这条「空槽自动补位」是刻意的：老数据（没有 `seats`）与「谁也没编辑过」的状态天生等价 —— `members=[mA,mB,mC]`、6 人间
得到 `[阿青, 小北, 老陈, 空, 空, 空]`，一个字都不用迁移。而**拖走就是拖走**：把 1 号床的人拖到 4 号床，
1 号床就空出来，不会把后面的人整体往前挤（`moveSeat` 只对调两格）：

- 拖前 `seatsOf` = `[mC, mD, mA, null, mB, null]`
- 实体化 `['mC','mD','mA','','mB','']` → 对调 0/3 → `['','mD','mA','mC','mB','']`
- 渲染出来就是 `空 | 大陈 | 阿青 | 老陈 | 小北 | 空`（真浏览器实测值，见 §五）

## 三、四条交互，各自的关键决策

### 1. 拖动：落点判定用「投影后的星位」而不是 DOM 命中

星点是绝对定位的小按钮，拖动时它跟着指针走（`--dd-dx/--dd-dy` 两个 CSS 变量每帧写上去，`transition:none`，
不然它会追着指针慢慢挪）。**落点不能用 `elementFromPoint`**：被拖的那颗星就在指针底下，会一直命中它自己。
所以松手时拿指针在取景框坐标系里的位置，去和**每颗星的真实投影坐标**比最近距离：

```js
const to = p ? bedSlotAtPoint(d.L, roomLive?.box || d.box, p.x, p.y) : -1;   // 半径 = 取景框宽 × 0.12
```

出框、坐标是脏值（NaN）、或者离所有星都太远 → `-1` = **什么都不做**（拖到空白处松手是取消，不是就近硬凑一张床）。
拖动中命中哪张床就给它挂 `.dd-bed.drop`（薄荷色光圈），松手落床后才把选中挪过去。

触摸上最要紧的是 `touch-action`：`.dd-room` 本来是 `pan-y`（上下拖可以滚页面），但**床上**必须完全接管指针 ——
`[data-room-edit="on"] .dd-bed{touch-action:none}`，否则手机上按住星星一拖就变成滚页面。卡片其余部分照旧能滚。

点选与拖动的分界沿用插件原有的 4px 阈值；只有真拖动才 `setPointerCapture`，`document` 级的
`pointermove/up/cancel` 只在按下去那一刻挂、松手立刻摘（不常驻监听）。

### 2. 重命名：名字就地变输入框，成员名与空床别名分开存

编辑模式下名字那块从「按钮 / 文字」换成 `<input class="dd-bed-name dd-bed-in">`：

- 床上有人 → 改的是**成员名**（`g.members[i].name`，沿用 `MEMBER_MAX = 12`）
- 床上没人 → 改的是**床位别名**（`g.bedNames[i]`，`BED_NAME_MAX = 10`）
- `Enter` 提交、`Esc` 放弃、失焦提交；值没变就只重绘、不落盘（避免一次 tab 切换写一次 storage）
- 别名**只在空床上显示**：睡着人时让位给成员名（否则「行李架」会盖住「阿青」）

原来的「点名字用 prompt 改名」**保留**（那条路能改成员名，且已有测试钉着）。空床加名字的意义在于：
星图上那句「空床」没法区分「这床没人睡」和「这床堆了东西」，起了别名之后一眼能看出来。

### 3. 连线：点两颗星连一条，有自己的线就不再画默认轮换线

- 编辑模式下点一颗星 = 选中（`.dd-bed.sel`，外圈实线；虚线在这个界面里是「连线」的语汇，所以选中刻意不用虚线），
  再点另一颗 = 连一条（`toggleLink`），再点同一颗 = 取消选中。
- `normalizeLinks(raw, size)` 会丢掉越界边、自环（`[2,2]`）、重复边（无向去重，留先出现的那个方向），上限 24 条 ——
  所以把人数档从 6 人间改回 4 人间，指向 5/6 号床的线**自己就掉了**，不会留一条指向不存在床位的线。
- 有自定连线时，**取代**默认那条围着所有星绕一圈的轮换折线（两条叠在一起谁也看不清）。
- 键盘 / 鼠标也能干完全程：编辑条里有「移到 X 号床」下拉（列出每张床的铺位、人名/别名/空）、「清空连线（N）」、
  「恢复默认床位」（带确认，只清 `seats/bedNames/links` 三样，**成员名单不动**）。

### 4. 编辑模式的开关与收尾

- 入口是星图工具条上的「编辑床位」胶囊（`data-room-edit`），开着时变实心并写「完成编辑」。
- 状态存在 `state.roomView.edit`，跟视角一起落在 storage 的 `roomView` 键里（`state.roomView` 本来就整体落盘）。
- 编辑模式下**不自动旋转**：`roomSpin()` 直接早退，否则边转边拖会拖空。
- 关掉编辑时 `roomSel = -1`：退出后 `.sel` 类、「已选中」播报一个字都不留（测试里钉了这条）。

## 四、顺手修掉的两个真问题

1. **拖星星松手后什么都不发生（只有真手势才暴露）**：`onStarUp` 里原本写 `apply((gg) => { … moveSeat(gg, …) … })`，
   但 `bind()` 传进来的 commit 是 `async (mutate) => { mutate(); … }` —— **回调不带参数**，`gg` 拿到 `undefined`，
   于是 `moveSeat(undefined, 0, 4)` 内部算出两张空床、`seats[a] === seats[b]`（都是 `""`）→ 静默 `return false`。
   症状极具迷惑性：星星跟着指针走完全程、落点高亮也对（实测 `drops=[1>0 2>5 3>5 4>4 5>4 6>4]`，说明落点算成了 4），
   但松手后数据一格没动、无报错、无写盘。**纯读代码看不出来**。改法：用 `bindRoom` 闭包里的 `g`；
   测试里加了一条源码守卫 `assert.ok(!/apply\(\([a-z]+\)\s*=>/.test(PLUGIN_SRC), 'apply 的回调不许带参数')`。
2. **实心按钮 hover 时字会消失**：`.dd-room-edit:hover` 把字染成 `--deep`，而 `.on` 状态的底也是 `--deep` ——
   深底深字。改成 `:hover:not(.on)`。
   同时 `.dd-room-edit.on` 从「12% 底 + `--deep` 字」换成与既有 `.dd-chip.on / .dd-gchip.on` **完全同一组令牌**
   （`--deep` 底 + `--on-deep` 字）：深色主题下原来只有 4.23:1（低于 AA 4.5），现在是 5.72:1。

## 六、影响面

- **桌面端**：只动轮换值日插件的星图区；轮换数学、提醒、任务、地点轮换、标签菜单都没碰。
  老数据没有 `seats/bedNames/links` → 行为与升级前逐位相同（`seatsOf` 退化成「第 i 位成员睡第 i 号床」）。
- **小程序端**：`dormDuty.js` 的归一化是 `Object.assign({}, base, usable ? raw : {})`，未知键**原样透传** ——
  桌面端写进去的 `seats/bedNames/links` 在小程序里读得到、写得回，不会因为那边不认识就被抹掉。
  小程序没有星图界面（星图本来就只有桌面端有），所以那边不需要为新功能改代码。
- **数据迁移**：无。三个新字段都是「不填就等于默认」的可选字段，落在整组 JSON 里，备份 / 导入导出 / 复制整套轮换
  （`duplicateGroup` 会把 `seats` 里的成员 id 一起重映射到副本的新 id 上，否则副本会是一片空床）都跟着走。
- **无障碍**：数字徽标的语义从「名单位次」改成**床位号**（挪过床位之后这两个数就不一样了），
  `aria-label` 变成「第 N 号床 · 上/下铺 · 谁 · 名单第 K 位」两个数分开播报，拖动/选中期间带 `aria-pressed`。
