# U-Time v0.106.0

APK 的下栏（点右上角 ⋮ 呼出的那条底部导航）从**贴底通宽**改成**悬空玻璃**。只改样式与守卫测试，
不涉及数据结构、无迁移、Windows 桌面端不受影响。

## 更新内容

### 手机底栏改为悬空玻璃（仅 Android / ≤900px）

#### 一、改了什么

改造前的底栏是 `position:fixed; left:0; right:0; bottom:0; width:100%`，只有上边一条描边、
阴影只往上方抛 —— 视觉上是「钉在屏幕底的一条」。v0.106.0 改成仓库里已有的悬浮面板配方
（对齐 `.quick-dock` 那颗玻璃面板）：

| 项 | 改前 | 改后 |
|---|---|---|
| 四周离屏 | 左右 0 / 底 0 | 左右 `--nav-float`（10px）/ 底 `--nav-float + --sab` |
| 圆角 | 无（通宽方条） | 四角 `20px` |
| 描边 | 只有 `border-top` 一条 | 整圈 `1px`（`--line` 78%） |
| 表面 | `--panel` 97% 近不透明 | `--panel → --paper` 半透明渐变 + `backdrop-filter: blur(18px) saturate(1.12)` |
| 阴影 | `0 -8px 24px`（只上抛） | `0 18px 44px` + `0 2px 6px`（四周浮起） |

底色全部走主题 token，**没有**新增 `[data-theme-mode="dark"]` 覆盖 —— 本项目的深色靠 token 换值
（见 AGENTS.md 铁律二「主题配色的分层」），所以六套配色 × 浅深色自动跟随，探针两种模式都截图核过。

#### 二、四条必须联动的地方（少改一处都是看得见的缺陷）

1. **安全区只算一遍**：`--sab` 从 `.rail` 的 `padding-bottom` 挪到了 `bottom` 偏移上。两处都留
   就是 v0.38.2「安全区被算了两遍」的同族 bug。左右仍走 padding 让开横屏挖孔（挖孔 inset 远大于
   10px 悬空量，得靠内边距把按钮让开）。
2. **三条让位一律 ÷ `--ui-scale`**：与 v0.105.1 同一个结论 —— `--sab/--sal/--sar` 是原生浮层的
   物理高度、恒定不变，而「界面缩放」是 `documentElement` 上的 CSS `zoom`，属布局级缩放。
   悬空条正是「拿自己的偏移去让开一条原生栏」的典型，0.7 档不除回来会被导航栏压住下缘三成。
3. **进出场位移**：`@keyframes rail-dock-in/out` 原来是 `translate3d(0, 105%, 0)` —— 105% 是按
   「条子贴底」算的。悬空之后要再走掉那 10px 缝隙，加上四周抛的阴影（上抛分量约 22px），
   改成 `calc(100% + var(--nav-float) + 24px)`，否则收起动画停在屏下时屏幕底缘会留一条边光。
4. **浮层底距**：`#toasts` 与 `.update-toast` 的 `86px` → `96px`（实测依据见下方表格），
   否则提示条会压在悬空条上 —— 底栏虽然半透明，两层玻璃叠着读起来就是糊在一起。

另外删掉了 v0.9 UI 层里那条 `@media (max-width: 900px) { .rail { background: …97%…; border-top: … } }`。
它写在移动端媒体块**之后**、同特异性靠后者胜，会把新的玻璃表面整个盖回不透明、并把 `border-top`
塞回来。底栏的几何与表面现在是一处事实源，那一层只留「按钮配色跟主题走」的覆盖。

#### 三、实测（无头 Chrome 390×844，注入 `--sat 40 / --sab 24`，探针 `output/probe-floating-navbar.mjs`）

悬空量与安全区在六档缩放下都保持**物理恒定**：

| 界面缩放 | 左边离屏 | 右边离屏 | 底边离屏 | 条子自身高度 |
|---|---|---|---|---|
| 1.0 | 10.0 px | 10.0 px | 34.0 px | 65.0 px |
| 0.889（288 宽手机自动缩） | 10.0 | 10.0 | 34.0 | 57.9 |
| 0.8 | 10.0 | 10.0 | 34.0 | 52.4 |
| 0.7（窄屏下限） | 10.0 | 10.0 | 34.0 | 46.0 |
| 1.25 | 10.0 | 10.0 | 34.0 | 80.8 |
| 1.5 | 10.0 | 10.0 | 34.0 | 96.5 |

底边 34px = 悬空 10 + 安全区 24，六档都不漂 ⇒ 除法生效。条子顶缘在屏幕底上方 99px
（标准档、缩放 100%）⇒ toast 那条写 `96px + --sab` = 120px，压在条子上方留 21px 缝。

还核过：收起态与收起动画终态屏幕底缘零像素残留；沉浸式插件页（课程表）里 ⋮ 呼出正常，
底栏悬空后压在课表网格上、透过玻璃仍能读出四个入口；浅色与深色两种模式各自成图。

#### 四、顺手记下的一条既有事实（本次未改）

底栏是**浮层**、不占流内高度：`:root[data-navbar] { --nav-pad: 54/62/70px }` 与
`.view { padding-bottom: calc(var(--nav-pad) + --sab) }` 那两条其实一直是死值 ——
被同媒体块后面那条 `(0,4,0)` 的 `.app:not(.chrome-shown):not(.rail-hidden) .view`
盖成了 `4px + --sab`。设置里「底栏高度」真正生效的是 `--nav-btn-h` 与 `--nav-ic`。
本次按既有语义继续把底栏当浮层，没有顺手改这条（改了会动所有页面的滚动区高度，
是独立一次改造）。

#### 五、守卫

- 新增 `scripts/test-floating-navbar.mjs`：钉住悬空量与三条让位的除法、玻璃表面必须走 token
  （写死十六进制底色就红）、整圈描边 + 圆角、`--sab` 不许再进 padding、关键帧位移必须算进
  `--nav-float`、`86px` 常量不许回潮、`translateZ(0)` 常驻合成层不许掉，
  以及**桌面竖栏不许跟着变玻璃**（它背后没有滚动内容，磨砂只会糊）。
- `scripts/test-chrome-toggle.mjs`：原来钉的是字面量 `translate3d(0,105%,0)`，改成钉新的
  `calc(100% + var(--nav-float)…)` 形状。

## 影响范围

仅 Android APK 与窄屏浏览器形态的外壳底栏。Windows 桌面（>900px）的左侧竖栏、小程序端、
插件侧代码与 API 全部不变；插件页画在 `render(el)` 容器里仍由宿主 `.view` 负责安全区，
不需要跟着改（`test-plugin-safe-area.mjs` 照旧通过）。无数据迁移。
