# v0.173.1 · 手机上复制整套轮换不再丢配置

## 改了什么

- 小程序端 `ddDuplicateGroup`（「⋯」→ 复制这套轮换）原本是一张**手写的字段清单**，
  只搬 id / 名字 / 起始日 / 周期 / 每轮人数 / 提醒相关的几个字段 —— 漏了
  **`locations`、`locationPeriodDays`、`pauseRanges`、以及当时刚加的 `roomSize`**。
  后果是在手机上复制一套「宿舍值日」，地点轮换和假期/节日暂停会**静默消失**，
  用户得在副本上白设一遍；桌面端因为写的是 `...src` 全带走，一直是对的。
- 现在小程序端也改成 `...src` 再逐个覆盖必须换掉的字段（id / 名字 / 成员 id / 换人记录 / 提醒标记），
  与桌面端同一条规矩。手写清单还有一个更隐蔽的毛病：**以后桌面端加新字段，这里不会报错，
  只会悄悄丢** —— 这次就是被它坑的第二次（上一次是加 `roomSize`）。
- 桌面端 `duplicateGroup` 本身无需改动，本次为它补上逐字段断言，两端行为一起钉死。

## 影响范围与数据迁移

- 只改 `miniprogram/core/plugins/dormDuty.js` 一个函数（页面层 `pages/plugin/dormDuty.js`
  只是转发到 `runtime`，没有第二份实现）。
- **无数据迁移**：只是以后复制出来的副本会带上原本就该带走的字段。已经被复制过、
  已经丢了地点/暂停段的旧副本**不会自动找回** —— 那些字段从来没写进副本里，无从恢复，
  需要用户在副本上补一次（或直接删掉重新复制）。
- Windows / Android 不受影响（桌面端本来就是 `...src`）。星图相关的 `roomSize`
  因此也一并被正确带走。

## 验证

- 新增跨端对等用例：桌面端与小程序端各复制一套带地点、地点周期、假期暂停段、
  宿舍人数档的轮换，逐字段断言副本内容；并加源码不变量
  「两端 `ddDuplicateGroup` 都必须出现 `...src`，不许退回手写清单」。
- **反向验证**：把小程序端那份的 `...src` 去掉，`npm run dorm-duty 测试`立刻报红
  （先撞在「起始日带走，两端同相位」上，说明手写清单连起始日都保不住）。改回后全绿。
- 真实应用端到端（`npm run dev` + 无头浏览器，真宿主真 API）：在「轮换值日」里
  逐个加 8 名成员、切 4→8 人间、切三个机位、刷新页面 —— 成员与人数档都保留，
  星图 854×641（窄屏 326×435 竖版取景框）、无任何页面错误。
- 三端版本一致 v0.173.1（Android `versionCode 17301`），118 个测试脚本全部通过。
