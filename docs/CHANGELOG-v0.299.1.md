# v0.299.1 · 考勤风险口径修正

> 发布日 2026-11-11 · 影响端：Windows / Android（两端同为 v0.299.1）· 无数据迁移

## 修的是什么

「考勤风险」上线后发现四处会算错账的地方，都在插件 `cppu-notify`（1.92.0 → 1.92.1），宿主壳只跟着升版本号。

| # | 现象 | 根因 | 现在 |
|---|---|---|---|
| A | 1 条「已同意」+ 1 条「未同意」，被标成「已超红线」 | `jwRiskApproved` 把 SQZT `2` 和 `3` 都当已批准；而本插件字典里 `3` = 未同意（`0` = 已撤销、`1` = 审批中、`2` = 已同意） | 只认 `2`；`1` 单独计审批中；`0`/`3` 按旷课计 |
| B | 本学期只请过 1 次，却显示已超线 | 请假记录接口返回全部历史，同名课上学期的单子被累加（课次 9 次只有 3 次额度，混进 3 条旧单就爆） | 按学期区间（校历 KSRQ/JSRQ，缺则用本学期课次上课日 min/max）先筛，排除条数写进页脚 |
| C | 课表「高等数学 A」有请假单，风险页显示 0 次 | 两侧课程名只用 `trim()` 做 key，全角空格 / 大小写差异直接漏配并被静默丢弃 | key 走 NFKC + 去所有空白（含全角）+ 转小写，与原版 `normalize` 同口径 |
| D | 只排 1 次课的课程，条形是空的却标「已超红线」 | 额度折不出 1 次时 `usedRatio` 直接返回 0 | 已批 > 0 时返回 1（原版 `getUsedRatio` 同口径），条形填满与红线标签一致 |

另外页脚补一句「N 条记录属别的学期，已排除 / N 条记录没对上本学期课表」，被过滤掉的数字不再静默消失。

## 没做什么

- 课次 → 学时（×2）、可缺额度（总学时 ÷ 3 再 ÷ 2 截断）、两条红线阈值、三级排序，全部与原版 `AttendanceRisk` 对齐，未改。
- 原版 `RiskFragment` 把 SQZT `3` 也算通过是它自身的缺陷，没有照抄。
