# v0.268.0 · 学生成长页加本地缓存：一个月内打开即出，不联网

## 改了什么

`public/plugins/cppu-notify/growth.js`（插件版本 1.75.0 → 1.76.0）

1. **快照落盘**：抓完把身份卡 / 学业概览 / KPI / 消费 / 上网 / 考勤 / 奖惩 / 模块入口写进
   `tide.cache`（`<数据目录>/plugin-cache/cppu-notify/growthSnapshot.json`），**不进 `data.json`**
   —— 那张 base64 头像与八块数据不该让每次保存任务都重写一遍主状态。
   只缓存能从磁盘恢复的字段；`error` / `stale` / `loading` / `tab` / `detail` 是「当下状态」的产物，缓存它们只会撒谎。
2. **30 天时效**：`FRESH_MS` 从 `60 * 1000` 改成 `30 * 24 * 60 * 60 * 1000`。
   一个月内再打开（**含重启应用**）直接画缓存、一个请求都不发；超过 30 天才自动重抓一次。
   手动「刷新」与重新登录成功仍走 `force`，绕过两条时效（否则主进程那份 10 分钟 TTL 缓存会把请求吃掉）。
3. **「更新于」说真话**：时间戳取**抓取那一刻**而不是打开那一刻；跨天自动带上日期（`M-D HH:MM`），
   `title` 里写明「一个月内直接显示本地缓存，不自动联网；点「刷新」可立即重取」。
4. **三条边界**（宁可重抓一次，也不许画空白）：
   - 坏快照（无身份卡 / 形状不对 / `savedAt` 为 0）一律当「没有缓存」；
   - 首屏齐但后五块全灭的那次**不落盘** —— 半页数据一存就是 30 天，会把「暂无」写死；
   - 老宿主没有 `tide.cache`（v0.247.0 才有）时静默降级成原行为，缓存只是加速不是必需品。

## 测试

- 新增 `scripts/test-cppu-growth-cache.mjs`（7 组断言，跑产品里那份真 `growth.js`）：
  首次抓完必落盘 · 30 天内新实例零请求且画出缓存 · 超过 30 天自己重抓 ·
  4 种坏快照退回取数 · 半页结果不盖掉旧快照 · 无 `tide.cache` 时降级 · `refresh()` 必须带 `force`。
- `scripts/test-cppu-speed.mjs`：重进窗口断言按文件分开（成长 30 天 / 个人信息 1 分钟），
  不再用同一条 `60 * 1000` 卡两页。

## 影响面

- 只影响「校园服务 → 学生成长」这一页；通知、教务、邮箱、上网记录、个人信息几块的缓存口径未动。
- 清缓存会重抓：删掉 `plugin-cache/cppu-notify/growthSnapshot.json` 即回到「首次进入」行为。
- 换账号：快照不按账号隔离，手动「刷新」一次即可覆盖（30 天时效内的旧数据不会自己消失）。
