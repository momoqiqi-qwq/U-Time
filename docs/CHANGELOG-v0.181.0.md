# v0.181.0 · 插件中心：滑块移到右下角 + 拖动卡片调整全部卡片大小

## 用户要求原文

> 「这个滑动开关还是改放在右下角
> 这个卡片的宽度和高度可以自行设置，我可以直接在这个界面，通过鼠标上下、左右拖动某一个插件卡片来自由调整全部插件卡片的大小。自动换行，自动适配界面。」

## 一、启停滑块挪到右下角

卡片操作区原来是 `justify-content: space-between`（滑块在最左、⋯ 在最右）。现在整条操作区一律右对齐
（`.market-card-actions { justify-content: flex-end }`），桌面端卡片底部只剩滑块，它就落在右下角；
窄屏条目是一行两列，再补 `align-self: end` 让它贴住条目右下角。
真机探针实测：滑块到卡片右边、下边的距离都是 17px。

## 二、拖动任意一张卡片 = 调整全部卡片的大小

新增 `src/marketCardResize.js`：

- **手势**：在卡片上按住拖动。水平位移改**网格列宽下限**，垂直位移改**卡片最小高度**，1px 位移 = 1px 变化。
- **起点取卡片当前实际尺寸**（不是偏好值）：宽是网格算出来的列宽、高是内容撑出来的高度，
  从这里起算才是 1:1 跟手。
- **点击与拖动的分界**：位移小于 4px 一律当点击（卡片点击 = 打开插件，不能被拖动抢走）；
  越过阈值才进入调整态，并在松手后拦一次 capture 阶段的 click，避免「拖完顺手把插件打开了」。
- **不抢控件**：按在启停滑块、⋯、以及任何 button / input / select / a / textarea 上都不介入。
- **不抢触屏**：`pointerType !== "mouse"` 直接放行 —— 触屏上拖动与页面滚动同义。
- **一处改、全部变**：尺寸写进 `:root` 的两个 CSS 变量（`--market-card-w` / `--market-card-h`），
  网格列宽与卡片最小高度都取它们，所以 18 张卡片一起变，不必逐张改。
- **落盘**：松手才写 uiPreferences（`marketCardWidth` / `marketCardHeight`），拖动过程中只改变量、不写存储。
- **取消**：拖动中按 Esc（或窗口失焦、pointercancel）还原到本次拖动开始前的偏好值，不落盘。
- **提示**：拖动中跟手显示「宽 220 × 高 120」。
- **回退**：网格空白处双击恢复默认（180 × 0）。
- 合法区间：宽 120–460、高 0–420。**高度 0 是默认值，意思是「不设最小高度、卡片随内容自适应」** ——
  这正是拖动前的行为，所以没拖过的用户看不出任何变化；往下拖才把卡片顶高。

自动换行与自适应仍由 `repeat(auto-fill, minmax(var(--market-card-w), 1fr))` 负责：列数按容器宽度自动算，
卡片宽度以你设的值为下限、均分剩余空间 —— 拖宽就少几列、拖窄就多几列，不溢出也不留大缝。

窄屏（≤900px）保持既有的单列紧凑条目：手机上卡片是横条而不是竖卡，宽度按屏宽自适应。

### 实现笔记：高度变量差点被一条老规则吃掉

先写的是 `.mcard { min-height: var(--market-card-h, 142px) }`，但探针量出来卡片高度纹丝不动。
查出真因：市场区块那条紧凑规则 `.market-manage-card{display:flex;…;min-height:0}` 写在 `.mcard` **之后**、
同特异性靠后者胜，一直把 `.mcard` 的最小高度压成 0 —— 也就是说**桌面卡片高度本来就不是 142px，一直由内容决定**。
本次把那一条改成 `min-height:var(--market-card-h, 0px)`，与 `.mcard` 指向同一个变量。
真机探针复验：默认 `--market-card-h: 0px` → 卡片高 100（随内容）；临时改成 220px → 卡片高 220，
同时 `--market-card-w` 由 180 → 300 让列数从 5 变 3、卡片由 190 变 323。

## 影响哪端

- 主要影响桌面端插件中心（拖动只有鼠标可用）；窄屏布局不受尺寸设定影响。
