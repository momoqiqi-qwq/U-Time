# v0.152.0

## 侧栏插件行尾的悬停操作条

桌面端侧栏的插件条目，鼠标停留约 0.3 秒后在行尾浮出两颗按钮（快速划过不闪，移开立即消失）：

- **… 更多** —— 打开该插件的菜单（重命名 / 修改图标 / 分组颜色与组名 / 快捷键 / 导入 / 删除），与原来的右键菜单是同一条路径。
- **📌 置顶** —— 把插件置顶到插件区最上方，再按一次取消。

操作条与原有的 `Alt+X` 快捷键徽标共用行尾悬浮位：操作条一现身，徽标让位，两者不叠字；不透明的底色会顺手盖住底下的「内置 / 导入」徽标。

## 置顶区

置顶插件从颜色分组里提出来，单独成块固定渲染在插件区最上方（极淡底 + 左侧竖条，与颜色分组卡片同一套视觉语言），置顶段内部可以继续上下拖动排序。

置顶只写 `settings.pinnedPlugins`，**不改动 `settings.pluginOrder`** —— 取消置顶后插件回到它在常规排列里的原位置，用户拖过的顺序与颜色分组都还在。右键菜单里也加了同一项「置顶在最上方 / 取消置顶」，键盘与触屏走那条路。

## 侧栏选中光效滑动

切换界面（含插件视图、插件中心）时，选中光效从旧位置**滑**到新位置，而不是旧位置闪灭 + 新位置闪亮。

- 新增一个独立的光块元素（`.nav-glow`）。原来选中态只是按钮自带的一块静态底色，而每次切换界面 `renderNav()` 都会把整个侧栏 `replaceChildren()` 重建 —— 静态底色做不出任何位移关系，所以观感是"两次独立出现"。
- **两层结构**：条目自持一层淡底（"自持微光"，α 5%）+ 光块作为"更亮的焦点标记"（α 10%）叠在其下。两层各管一个语义 —— 选中项落进**收起的分组**、由组头替它亮着时，光块淡出而那层微光仍在，侧栏不会整个失焦。
- **动效参数**：位移 500ms `OutBack`（overshoot 1.3，即"带惯性"的过冲回弹）、尺寸 400ms `OutCubic`。两条通道**刻意的时长不等**（5:4）：行高有差时那一帧的不同步就是"拉伸感"的来源，比显式缩放自然。
- **两端一致**：桌面竖栏竖向滑，窄屏底栏横向滑，同一套算法；跟随侧栏宽度拖拽 / 窗口 resize / 界面缩放 / 分组折叠 / 容器尺寸变化瞬时对齐；连续快速切换从**当前视觉位置**续播，不回退到起点。
- **减少动效**（设置里的"减少动效"或系统偏好）为真时直接落位，不播滑动。无新增设置键，无需迁移。

> 参考实现：Nephele Workshop 侧栏的 `sidebarActiveIndicator`（其 QML 源码随包分发，直接读到了参数与设计意图）。上面的两层结构与 500/400 双通道时长都取自它。

### 真机逐帧验证时发现并修掉的四处

动效靠肉眼在正常速度下看不准，所以用无头 Chrome + CDP 真实时间驱动、把动画**定格**在 0/90/180/270/360/500ms 取帧，再核 DOM 几何。过程中挖出三个真问题：

1. **终点坐标用了"含按钮自身 transform 的视觉位置"** —— CSS 给所有 `button` 挂了 hover 抬升（`translateY(-1px)`）与 `:active` 下压（`translateY(1px) scale(.98)`），两者都带过渡。切页那一刻按钮正在过渡中间，读到的是瞬时反馈的位置：实测终点偏 1px；极端情况（`:active` 的 `scale(.98)` 还没退完）宽度会差 2%。光块是**选中指示器**、锚定的是"这一行的位置"，不该跟着 hover 抖 —— 鼠标一移开按钮回落，跟着抖的光块反而会永久错位。现在统一过一层 `layoutBoxOf()`：读自身 transform 反解出布局盒（`transform-origin` 是 center，缩放绕中心、位移直接减；有旋转/斜切就退回裸 rect）。修完实测「鼠标移开 = 光块与选中行 Δl/Δt/Δw/Δh 全 0」。
2. **宽屏（≥901px）侧栏在浅色主题下光块隐身** —— 那个媒体块把 `.rail` 换成了主题令牌驱动的**浅色面板**（`--panel`/`--paper` 混），`.nav button.on` 也跟着换成了 `--active-bg`，但光块还落在基础规则那块 `rgba(255,255,255,.10)` 上。白叠在浅底上合成只差 1 个色阶，逐帧截图零差异（深色主题正常，所以只看深色会漏掉）。现在宽屏块里跟着同块的 `.on` 走同一个令牌（选中行 `--deep` 10%，光块 `--deep` 20%）。
3. **窄屏呼出底栏后没有选中光块** —— 底栏是 `display: none ⇄ flex` 切换，光块的包含块就是 `.rail`；包含块从"无"变"有"时没人落位，于是底栏先滑出来、光块要等下一次切页才淡入。**不能指望 ResizeObserver 兜住**：窄屏下 `.nav` 是 `display: contents`、不生成盒子，RO 对它恒报 0×0，"底栏显隐"这件事它完全看不见（已实测）。改为在底栏显隐处显式落位一次。
4. **插件视图那条路径一直是验证盲区，而问题恰好藏在里面** —— 取帧脚本挑目标时特意写了 `filter((b) => !b.id.startsWith("plug:"))`，理由注释是"插件项会让 market 一起亮，判据变脏"，于是"切到插件视图"始终没被覆盖。补测后发现：进插件视图时 `market` **也**带 `.on`（`navBtn` 里 `id === "market" && activeView.startsWith("plug:")`，这是**刻意**的 —— 插件是从市场进去的，两个都该亮），而 market 在核心页清单里、文档序排在插件段**之前** ⇒ 光块取 `querySelector('button[data-view].on')` 的第一颗，拿到的正是 market：切过去后光块停在「插件市场」不动，离目标行差 **78px**（近两行）。现在多颗 `.on` 并存时以 `activeView` 自身那一项为准；它不在 DOM 里（插件项被折叠的分组藏起来）才回退到第一颗。修完实测 `quadrant → plug:cppu-cx`（跨 292px）光块落定与目标行严丝合缝，并且**第一次**看到 400ms 尺寸通道真的在跑（行高 40 → 42）—— 等宽页签之间那条通道一直被短路，只有跨尺寸才现身。

## 影响范围与迁移

- 只在桌面端侧栏生效：APK / 手机端侧栏是底栏、没有 hover，长按又已归拖拽排序，故不挂操作条。
- 新增设置键 `settings.pinnedPlugins`（插件 ID 数组），旧数据无该键即视为没有置顶，无需迁移；该键随同步快照一起同步。
- 插件中心的排序不受置顶影响，仍按原有分组与顺序展示。
